# 12 · 框架审核评估（v0.9，2026-11-01）

> 结论先行：**规范与流程达到工业级，出片稳定性还没有被一部完整成片验证。** 所以打包为 v0.9（发布候选），跑通一部完整片、记下每条的抽卡次数后再升 1.0。

## 二、本次补上的缺口

1. **视频提示词双方案**：每条交 A 预演版 + B 无预演版，同一场戏、同一套台词与切点，写推荐理由；lint 分别检查并核对两版一致（docs/09 第 3.3 节）。
2. **白模预演从手工变成工具**：`tools/previs/render_previs.py`，写一份镜头规格 JSON 就出预演视频和关键帧拼图，不用每条手写 Blender 脚本。
3. **出图从单一平台变成多接口**：`tools/image_gen.py` + `config/image_providers.json`，支持多米、OpenAI、OpenAI 兼容中转、Google Gemini、火山方舟；资产文档每张图标推荐模型和理由，接口不全时自动顺延到备选模型；`--dry-run` 先看路由不计费。
4. **去平台化**：密钥只走 `.env`；Blender 与图像格式转换不再依赖 macOS 专属命令（Pillow / sips 二选一，都没有则保留原格式）。
5. **立项多问两件事**：接了哪几家出图 API、本机有没有 Blender（决定能不能交 A 版）。
6. **样本提炼进规则**：用户收集的 6 条高质量 Seedance 提示词提炼为第 27–40 条；用户喜欢的 12 部短片提炼为故事灵感库。

## 三、仍然存在的风险（如实列出）

1. **没有一部完整成片验证过新规则。** 《潮水来之前》第 2 条的事故催生了第 18–26 条，但改后的提示词还没重新出片。升 1.0 的条件：一部 ≥90 秒的片全部条目出片，记录每条抽卡次数与翻车原因，回填圣经第九节故障表。
2. **除多米外的四种接口未用真实密钥实测。** 请求格式按官方文档实现，并用本地模拟接口验证过请求体与返回解析；模型 id 会随厂商更新，已做成环境变量。第一次接入时先用 `--only 1` 出一张验证。
3. **规格 JSON 只能表达方块、人物和机位。** 斜坡、台阶、水位、扫光这类仍需手写脚本（有两份完整范例）。
4. **视频生成不自动化。** Seedance 出片由用户在网页端操作（贵，工厂规则禁止助手自行付费生成）。火山方舟有视频 API，需要时可另做脚本，但每次提交都要用户确认费用。
5. **成片质检靠人眼。** 审片 24 分制目前是人工打分；可以接视觉模型做初筛，尚未实现。
6. **文档体量大**（约 14 万字）。入口 SKILL.md 按阶段指路、按需加载章节；上下文很小的智能体可能需要只加载 SKILL.md + docs/09 + docs/02。

## 四、接下来升级到 1.0 要做的事

1. 用一部新片（按 docs/11 出创意）跑通全流程，A/B 两版各出几条做对照，记录抽卡率。
2. 每家出图接口各出一张三视图和一张场景图，把实测结果写回 docs/10。
3. 把出片翻车案例按"现象 → 根因 → 规则编号 → 改法"补进圣经第九节。
