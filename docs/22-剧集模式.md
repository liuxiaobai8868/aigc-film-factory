# 22 · 剧集模式（短剧、漫剧，一集一集来）

> 2026-11-06 建（工厂 4.0 第三期）。借鉴 [ai-manju-skills](https://github.com/wp746/ai-manju-skills) 的做法：全季企划、逐集推进、钩子、卡点、状态卡、背影卡、发布包。没有照搬的部分：题材一样要过 docs/20 的内核闸门（总裁甜宠、重生复仇这类，主角也要自己选择、付出代价）；约束写成肯定句，不用负面提示词；一律走流水线，不靠分批粘贴。
> 样例：`examples/样例-剧集/`（两集、9:16、一张状态卡、一个第 2 集才揭开身份的人、一段冷开场）。自测：`python3 tools/pipeline.py selftest examples/样例-剧集`。

---

## 一、单片和剧集的分工

| | 单片（docs/09） | 剧集 |
|---|---|---|
| 设定（人物、场景、道具、群像、类型卡） | 项目里的 `设定.json` | 剧目录的 `设定.json`，全季共用 |
| 资产图 | 项目里出 | **剧目录出一次，各集共用**；后面的集新增资产时只出新增的 |
| 分镜、白模、投喂包 | 项目里 | 每集一个目录 `ep01/`，跑自己的 |
| 用户确认 | 故事、剧本、出图花费、出视频花费 | 全季故事和设定确认一次；**每集剧本确认一次**；花钱照旧问 |
| 额外的交付 | — | 每集一份 `交付/发布包.md` |

## 二、目录

```
projects/<剧名>/
  季圣经.md            给人看：世界、人物弧光、全季逐集大纲、伏笔回收表、卡点集、类型卡
  季.json              给流水线：每集的标题、剧情、钩子、卡点、发布文案；伏笔表；每集时长、画幅、台词量
  设定.json            全季共用（docs/19 格式），加 ratio、状态卡、背影卡、reveal_ep
  production.json      全季：确认、出图预算、资产目检
  交付/01-资产提示词.md、交付/资产图/、交付/参考图定版/
  ep01/
    分镜.json          这一集（docs/19 格式，加 ep、hook、opens_with）
    production.json    这一集：剧本确认、白模目检、各阶段
    交付/规格单/、交付/投喂包/、交付/发布包.md、logs/
```

## 三、流程

1. **立项**：类型卡和时长（docs/21）；再问集数、每集时长、画幅（短剧默认 9:16）、更新节奏。
2. **① 全季故事**：先给 3 个方向，用户选定后写 `季圣经.md`：
   - 一句话、人物和弧光、全季逐集大纲（每集 2–3 句 + 结尾钩子）；
   - 伏笔回收表、付费卡点集；
   - 悬疑类另写**真相时间线**（精确到分钟）、**线索表**（每集出现哪条线索、指向谁、是误导还是真相）、**谁说真话谁说假话**的对照表。先定真相，再决定怎么藏。

   **全季结构**（2026-11-07，docs/23 第七节）：
   - 前 3 集决定生死（样本里第 1 集到第 6 集播放量掉了 79%），前 3 集每集一次大翻转；
   - 起承转合按集数大约 6% / 17% / 61% / 16%，"转"由 2–6 集一块的事件块组成，每块一个对手、一次翻转，对手接力、一级比一级大；
   - 压抑不超过 3 集必须释放；同一类集尾钩子不连用 3 次（钩子十二类见 docs/23 第六节）；
   - 中段高光可以用"甜到顶点 + 身份揭穿 + 当集翻脸"叠在同一集（样本里唯一有播放量数据的一条：这一集是前后几集的约 4 倍）；
   - 身份揭晓排期写进季圣经；每 10 集至少 3 个观众会在评论区吵的选择。

   用户确认后 `pipeline.py confirm <剧> story`。
3. **② 全季设定**：`设定.json` + `季.json`。用户确认后 `confirm <剧> script`，然后 `pipeline.py run <剧>` 出全季资产（报张数和花费，用户点头再 `approve <剧> images N`），目检。
4. **逐集**：
   - `pipeline.py episode <剧> 01` 建集目录；
   - 写这一集的剧本，用户确认后 `confirm <剧>/ep01 script`；
   - 拆 `ep01/分镜.json`，`storyboard.py check <剧>/ep01` 改到通过；
   - `pipeline.py run <剧>/ep01`，一路跑到投喂包和发布包。
5. 后面的集用到新人物、新场景，先加进剧目录的 `设定.json`。跑这一集时流水线会回到剧目录，只给新增资产出图，并照样报花费。
6. `pipeline.py status <剧>` 看全季：资产到哪一步，每集到哪一步。

## 四、数据

**季.json**

```json
{"title": "剧名",
 "series": {"episodes": 30, "ep_seconds": [180, 300], "ratio": "9:16", "dialogue_per_min": [75, 130]},
 "episodes": [{"ep": "01", "title": "集名", "summary": "2–3 句剧情", "hook": "结尾钩子：一个画面或一句台词", "hook_type": "半句话", "tag": "压", "info": "这一集投放的新信息", "paywall": false,
               "titles": ["钩子标题 ×3"], "blurb": "80–120 字简介", "tags": ["话题 ×5–8"], "pinned": "置顶评论（可选）"}],
 "foreshadow": [{"what": "伏笔", "plant": "01", "payoff": "05"}]}
```

**设定.json 新增字段**

- `"ratio": "9:16"`：白模渲成竖屏，四家投喂包的比例都写 9:16。
- **状态卡**：人物的 `variants`，比如受伤、疲惫、湿透。
  - 变体名可以直接写进 `cast`，身高、音色、白模颜色都跟着本人走，参考图换成变体那张。
  - 状态卡**只进不退**：先出现过"湿透"，后面又回到干的，校验器会提醒；确实有休息或治疗的情节，在那一条写 `state_reset`。
- **钩子类型和功能标签**（可选，2026-11-07）：每集写 `hook_type`（十二类之一：生死悬停、身份揭晓、半句话、更大对手、反常陈述、宣战、认知颠覆、亲密打断、喜剧定格、物证特写、时间戳循环、规则宣告）、`tag`（铺垫 / 推进 / 压 / 放 / 反转 / 揭示 / 钩 / 余韵）和 `info`（这一集投放的新信息）。校验器提醒：同一类钩子连用 3 次、连续 3 集同一个标签、连续 4 集都是"压"。
- **背影卡**：身份还没揭开的人，在人物上写 `"reveal_ep": "05"`，再加一个 `"back_view": true` 的变体（只出背影或遮脸）。第 5 集之前 `cast` 里只能用背影卡，用了本人就报错。

**ep01/分镜.json 新增字段**

- `"ep": "01"`：和目录名一致。
- `"hook"`：这一集的结尾钩子，和 `季.json` 一致。
- `"opens_with"`：第 2 集起，开头怎么接住上一集的钩子。
- **冷开场**：放在最前面的一条，写 `"cold_open_of": "3"`，表示它是第 3 条的闪前。台词必须一字不差地出现在第 3 条里（后期用同一条录音）。条号可以用 `"0"`。

## 五、校验器查什么

| 级别 | 查什么 |
|---|---|
| 报错 | 集号不在 `季.json` 里；缺 `hook`；冷开场台词和对应的条对不上；身份揭开前用了本人；伏笔集数不存在或回收在埋下之前；`季.json` 某集缺 summary 或 hook |
| 提醒 | 同类 `hook_type` 连用 3 集；连续 3 集同一 `tag`；连续 4 集"压"（压抑不超过 3 集）；缺 `opens_with`；这一集时长不在 `ep_seconds` 里；每分钟台词字数不在 `dialogue_per_min` 里；状态卡倒退；发布文案没写；还有集没写分镜 |

**每分钟台词量参考**（ai-manju 的经验）：
- 悬疑、宫斗、商战这类靠对话推进的：约 75–130 字 / 分钟；
- 动作、奇观类：可以低到 40–60 字 / 分钟。

台词太少，一集撑不住；太多，画面就没有呼吸。

## 六、发布包（流水线 publish 阶段自动生成）

- **封面**：竖版 3:4 和横版 4:3 两份出图提示词。
  - 取这一集能量最高那一条的视听高光镜头（不用冷开场），去掉台词和声音；
  - 主角脸朝镜头、在画面中上部，顶部三分之一留给后期加的标题；
  - 标明要上传哪几张参考图。出封面图前照样报张数和花费。
- **片尾和下集预告**：片尾卡 3 秒；下集预告取下一集最强的 2–3 个镜头加一句台词，接在正片之后，不占正片时长。
- **文案**：钩子标题、简介、话题、置顶评论，从 `季.json` 取；没写的话流水线会停下要你补。
- **合规**：标注 AI 生成内容；不用绝对化用语、真实人物肖像和真实品牌。

## 七、竖屏注意

- 横屏的全景机位放进 9:16 里，两侧的人会出画。4.0 alpha.7 起**自动修**：全景镜头写了 `who` 的，按几何检查同样的时刻（25% / 50% / 75%）、连运镜一起算，先把机位转最少的角度把这些人装进来（尽量保住原构图），装不下再换广一点的镜头（最广 18 mm），还装不下就沿视线往后退。巨物和画外音不算。某一镜不想被改，写 `"keep_view": true`。
- 黄金分割的 38% / 62% 按竖屏的水平视场角算（竖屏比横屏窄得多）。
- 几何检查仍会拦"头不在画面里"；自动修不了的（比如往后退会撞墙），照旧改 `views` 或让全景只拍一两个人。
- 资产图仍是 16:9 的三视图和场景图，只作参考，不影响竖屏出片。
