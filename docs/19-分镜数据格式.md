# 19 · 分镜数据格式（设定.json + 分镜.json）

> 剧本确认后，智能体唯一要"写"的东西就是这两份 JSON。机位坐标、"画面里"那句话怎么写、说话人怎么写、群演怎么点名、过肩选哪一侧、每条带哪些参考图，全部由 `tools/storyboard.py` 按固定规则算，所以**同一份数据，任何智能体跑出来都一样**。
> 标准样例：`examples/样例-便利店/`（剧本 `03-剧本.md` → `设定.json` + `分镜.json`）。动手前先读一遍样例，照它的写法拆。
> 写完跑 `python3 tools/storyboard.py check projects/<项目>`，每条 ERROR 后面都写了怎么改，改到"通过"为止。

---

## 一、拆剧本的固定步骤（照顺序做，不跳）

1. **列人物**：剧本里有名字、有台词或有特写的人，进 `characters`；没名字的路人不进，进群像。
2. **列场景**：每个地点一个 `location`，给它搭一个简单白模（地面尺寸 + 几个方块）和站位点 `marks`。
3. **列道具**：剧情要靠它推进、会被特写的物件，进 `props`。
4. **列群像**：每个有路人的世界一张群像，14 人，每人写身高（docs/17）。
5. **分条**：每条 4–30 秒，一条只在一个地点，一条只拍一组对话（一条轴线）。
6. **分镜**：剧本里每个【】一镜，按第三节的字段填；台词照抄剧本，一字不改。
7. **跑 check**，按 ERROR 改，直到通过。

## 二、设定.json

```json
{
 "title": "片名", "short": "短名（文件名前缀）", "film": "near-live-action cinematic short film",
 "worlds": {"世界名": {"recipe": "R05"}},          // 每个世界一个风格配方（docs/16，tools/mj_style.py --recipes）
 "people_recipe": "R04",                             // 人物、道具用的配方
 "core": {"want": "主角想要什么", "need": "真正需要什么", "choice": "关键时刻自己做的选择", "cost": "选择让他失去什么", "image": "说出主题的那个画面"},   // 必填，docs/20 第三节；出现等救主结构会被拦
 "look": {"genre": ["G18", "G17"], "tier": "1-3"},   // 可选（4.0 起立项必填）：类型卡和时长档位，见 docs/21；校验器按卡检查配方、平均镜长、禁用运镜，按档位检查时长、条数、场景和角色数（只提醒）
 "three": "世界锁：……",                              // 一段中文：有几个世界、各自什么样、怎么拍
 "music": "配乐：……",                                // 一段中文：每个世界的配乐 / 环境声
 "anchor_extra": "（可选）补充的硬约束",
 "characters": [{
   "name": "阿青", "height": 1.62,                    // 身高（米），白模和过肩机位都用它
   "mark_zh": "深蓝工装、左手旧电子表",               // 一句识别特征，进"人数锁"
   "silhouette": "齐肩黑发、偏瘦的肩、深蓝工装",       // 必填：剪影识别点，只看轮廓就认得出（crew/07）
   "lock": "阿青：……",                               // 中文描述锁，逐字进每条规格单；不写岁数和年龄词
   "brief_en": "a tired young night-shift clerk, clearly an adult in her early twenties.",
   "must_en": "必须看得清的服装、道具、发型（英文）",
   "portrait_en": "大头像的表情（英文，可省）",
   "check": ["出图后检查项"], "voice": "音色锁（中文）",
   "variants": [{"name": "阿青_湿透", "lock": "……", "edit_en": "she is soaked by rain …", "check": []}],   // 可选：状态变体
   "kind": "giant"   // 可选：giant = 巨物（怪兽、机甲、巨人），出"自然姿态三分之四正面 + 侧面 + 局部特写"的设定图，不做脸模糊，配方用 recipe 或 giant_recipe（默认 R15）；
                     //       voice = 只有声音（电话、广播、对讲机），不出图、不进 cast，只写 voice / voice_en，台词 mode 写 off
 }],
 "props": [{"name": "香烟", "lock": "……", "en": "……", "must_en": "……", "check": [], "ref": "阿青",
            "mechanism": "手怎么动 → 道具怎么响应 → 结果状态"}],   // 镜头里被手操作的道具必填（crew/06）   // ref：随某人物出现时以其三视图为参考
 "locations": [{
   "name": "便利店", "world": "世界名", "lock": "……", "en": "……", "must_en": "……", "check": [],
   "anchor": ["锚点物 1", "锚点物 2"],               // 必填：观众记得住、模型钉得住的东西
   "light": "光逻辑：主光、位置、色温；辅光从哪来",     // 必填
   "era": "时代锁：可以出现 / 不能出现的物件",          // 必填
   "wear": "使用痕迹：磨亮、水渍、胶带……",              // 必填（以上四项进资产提示词的"美术要求"和视频提示词的空间段）
   "contrast": "画面对冲：明暗 / 冷暖 / 大小 / 新旧 / 静动", // 必填（docs/20 第四节"张力"），同样进"美术要求"
   "grid": false,                                     // true 时多出一张 2x2 多视角宫格
   "human_view": false,                               // true 时按"人类视角机位"出（人间纪实镜头）
   "stage": {
     "size": [12, 12],                                // 地面宽、深（米），场景原点在中心
     "boxes": [{"name": "Counter", "min": [x,y,z], "max": [x,y,z], "color": "wood|white|stone|dark|red|gold|glass"}],
     "marks": {"收银台后": [x,y,z]},                  // 站位点和物件点（米）；分镜里只用这些名字
     "establish": {"pos": [x,y,z], "look": [x,y,z] 或 "站位名", "lens": 24},   // 默认全景机位
     "views": {"朝门口": {"pos": …, "look": …, "lens": 24}}                   // 其他固定机位（可选）
   }}],
 "crowds": [{"world": "世界名", "refs": ["阿青", "老周"], "world_en": "……",
             "roster": [["中文一句", "English one line, about 170 cm tall"], … 共 14 个]}]
}
```

坐标约定：x 向右，y 向前（远离镜头），z 向上，单位米；`color: glass` 的方块视为透明，不算遮挡。

## 三、分镜.json

```json
{"clips": [{
  "n": "1", "title": "……", "location": "便利店", "summary": "一句话", "context": "这条之前发生了什么",
  "cast": {                                            // 本条出场的人和站位
    "阿青": {"at": "收银台后", "face": "门口"},          // face：站位名 / 人名 / 角度
    "老周": {"path": [{"t": 0, "at": "门外"}, {"t": 8, "at": "门外"}, {"t": 10, "at": "柜台前"}], "face": "收银台后"}
  },
  "props": ["香烟"],
  "shots": [ … 见下表 … ],
  "turn": {"from": "开头的处境", "to": "结尾的处境"},          // 必填：价值翻转，两头相反（docs/20 第四节）
  "signature": {"shot": 3, "why": "构图、光、运动、声音怎么同时发力"},   // 必填：这一条的视听高光镜头
  "tension": "谁想要什么、什么挡着、观众比角色多知道还是少知道什么",       // 必填：压力源（docs/20 第四节"张力"）
  "stillness": "（可选）整条有意不动机器时写：为什么要静、静之后哪里爆发",
  "energy": {"in": 2, "out": 4},                        // 必填：这一条开头和结尾的情绪强度 1–5，排全片曲线
  "drama": {"a": "一方想要什么", "b": "另一方想要什么", "shift": 3},   // 两个以上的人说话时必填：优势易手那句在第几镜（crew/22）
  "time_jump": "（可选）和上一条同一场景但跳过了时间：跳过了什么",     // 不写就要求站位接上，并自动接上一条尾帧
  "constraint": "本条的硬约束（中文）", "fail": "失败判据", "risk": "最可能翻车的点", "splice": "出口：……",
  "model": "Seedance 2.5 + 白模"
}]}
```

| 镜头字段 | 说明 |
|---|---|
| `dur` | 秒，≥ 1.5；全条加起来 4–30 |
| `type` | `wide` 全景（用 establish 或 `view`）· `single` 单人 · `ots` 过肩 · `insert` 物件插入 · `track` 跟拍 · `pov` 主观 |
| `size` | 大特写 / 特写 / 近景 / 中景 / 全景 / 大全景（决定焦距和机位距离） |
| `subject` | 拍谁（single / ots / track / pov 必填） |
| `fg` | 过肩越过谁的肩膀（ots 必填）；一条里只能有一组 fg–subject |
| `who` | 画面里另外还有谁（wide 必填） |
| `object` / `hand` | insert 拍哪个 mark；有动作就必须写 `hand`：谁的手、什么样、袖口；确实没有手写 `no_hand: true` |
| `look` | pov 看向哪里 |
| `view` | wide 用哪个固定机位（stage.views） |
| `line` | `{"who": 说话人, "text": 台词, "mode": "on|back|off", "delivery": "压低声音、说到一半停住"}`；on = 在画里说，back = 过肩前景背对镜头说，off = 画外；**有台词的镜头必须先写一个手上动作**，台词用标点写出呼吸（crew/23 让台词像人说的五条） |
| `action` | 一句中文，或 `{"at": 秒, "text": …}`；**有台词的镜头最多一个动作** |
| `sound` | `[{"text": "推门的风铃声", "source": "门口"}]`；source 是画里的发声者、站位，或 `"画外"` |
| `crowd` | `{"ids": [2, 5, 9], "doing": "在门外躲雨，陆续走开"}`；动作里写到路人就必须点编号 |
| `move` | 有动机的运镜：`{"kind": "push|pull|truck_left|truck_right|rise|drop|orbit_left|orbit_right|handheld", "speed": "slow|steady|sudden", "why": "动机", "amount": 0.4, "to": "（可选）结束景别，如 近景"}`。程序按起始机位自动算终点（推拉走掉机位到主体距离的 amount，横移 / 升降 amount × 距离米，环绕约 35°×amount/0.4），白模几何检查会查起止两端的构图；中文写成"镜头缓慢推近"，英文写成 "the camera pushes in slowly"。`why` 必填；track / pov / cam 自带运动，不能再加；`sudden` 单镜不短于 2 秒 |
| `hit` | 武戏：`{"support": 支撑, "force": 发力, "contact": 接触, "reaction": 受力, "result": 结果, "en": 英文一句}`。动作里出现打、踢、砍、摔、撞、追等词时必填（crew/17 逐击五步因果），写进提示词的"动作因果" |
| `vfx` | 特效：`{"source", "direction", "scale", "speed", "medium", "light", "decay", "en"}` 七要素。动作里出现爆炸、火焰、魔法、能量、光束、变身、闪电、发光等词时必填（crew/18），写进提示词的"特效" |
| `cam` | 逃生口：`{"pos": …, "look": …, "lens": 50, "end": …}` 直接给机位（只在规则算不出想要的机位时用） |
| `allow_occlude` / `allow_small` | 有意的遮挡 / 有意拍得很小的人（几何检查放行） |

## 三·五、要出海螺 H3 时补的英文字段

海螺 H3 官方提示词是英文分段格式（docs/13 第六节）。项目 `production.json` 的 `video_models` 里有 `hailuo` 时，校验器会要求下面这些英文，**写一次，编译器原样使用，不临场翻译**：

| 位置 | 字段 |
|---|---|
| 设定.json | `music_en`（没有配乐写 "N/A"）；每个人物 `voice_en`（音色：性别、音调、语速） |
| 每条 | `summary_en` |
| 每镜动作 | 写成 `{"at": 1, "text": "中文", "en": "English"}` |
| 每镜声音 | `{"text": …, "en": …, "source": …}` |
| 群演 | `crowd.doing_en` |
| 插入镜头 | `object_en`、`hand_en` |

台词不用翻译：H3 官方要求台词保留原文，编译器写成 `<d>[Chinese] 台词</d>`。

## 四、校验器会拦什么（全部是实拍或白模里踩过的坑）

| 拦什么 | 来源 |
|---|---|
| 没写故事内核 core，或内核里有等救主结构（认亲、系统、战神、赘婿、跪地求复合……） | docs/20 第一、三节 |
| 每条没写价值翻转 turn 或视听高光 signature | docs/20 第四节 |
| 场景缺锚点物 / 光逻辑 / 时代锁 / 使用痕迹；人物缺剪影识别点；被操作的道具缺操作机制 | crew/06、07 |
| 人物描述写了毛孔、瑕疵、颗粒 | docs/16（出图模型会画成砂纸皮肤） |
| 对白镜头没有动作；长台词没有停顿 | crew/23 |
| 每条没写压力源 tension；场景没写对冲 contrast；运镜没写动机 why | docs/20 第四节"张力" |
| 全片能量最高不到 4、全片只有一两档能量；每条都低能量收尾（提醒）；三条以上没有加速段（提醒） | docs/20 第四节"张力"，《最后一次采血》复盘 |
| 对手戏没写 drama，或优势易手那句给了全景 | crew/22 |
| 动作里有打斗词却没写 hit 五步；有特效词却没写 vfx 七要素 | crew/17、18 |
| 同一场连续的两条，人物站位没接上（又没写 time_jump） | crew/12、docs/07 |
| 节奏四平八稳：镜头时长最长不到最短的 1.5 倍；整条全是固定机位又没写 stillness；相邻两镜类型和景别都一样；一条不到三种景别（提醒） | docs/20 第四节"张力"、docs/14 第三节 |
| 描述锁写了岁数、年龄词 | 合规 + 第 1 版小雷"像孩子" |
| 说话人不在画里又没写 back / off | 台词串人 |
| 台词超过 4.5 字/秒 | 说不完 |
| 有台词的镜头塞了多个动作 | 第 1 条"光环闪、弹光环"被忽略 |
| 插入镜头有动作却没写是谁的手 | 第 1 条拇指变成别人的食指 |
| 动作写到路人却没点群演编号 / 没有群像 | 第 1 条长廊没人 |
| 声音没写声源 | 第 1 条长廊没声 |
| 一条里过肩换了两组人 | 越轴 |
| 站位、人物、道具、机位名字写错 | 漏读误读 |
| 镜头短于 1.5 秒、全条超过 30 秒 | 模型做不出 / 超出上限 |

**只提醒、不拦的（4.0 起）**：画面里的文字、镜子和倒影、人物交叉、一镜内换光、多人同一秒做同一个动作、一镜动作超过两个（Eian 实测的 AI 弱点，docs/14 4.2）；类型卡和时长档位不符（docs/21）。

几何检查（Blender 白模里）再拦：主体不在画里、被挡住、太小、头后竖直物、机位穿墙、越轴、过肩前景出画。WARN 也拦。

## 五、自测

任何智能体、任何机器第一次用本仓库，先跑：

```
python3 tools/pipeline.py selftest examples/样例-便利店
```

不花钱（占位图），从样例数据一路跑到四个模型的投喂包，再和 `examples/样例-便利店/标准产物/` 逐字比对。不一致就说明环境或代码被改坏了，先修好再生产。改了框架代码、确认新产物正确时，才用 `--update` 更新标准。
