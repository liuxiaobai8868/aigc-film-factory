# 出图模型技巧：Image 2.5 / Nano Banana / Seedream / Midjourney

> 每张资产图在《资产提示词》出图清单里标一个**推荐模型**和理由，用户可以改。本文件是四种模型的选型、写法、参数和接口记录。
> 出图脚本：`tools/image_gen.py`——按推荐模型选引擎，按已配置的 API 选接口（多米 / OpenAI / OpenAI 兼容中转 / Google Gemini / 火山方舟），配置在 `config/image_providers.json`，密钥放 `.env`（见 `.env.example`）。多米接口 2026-10-31 实测；其余接口按官方文档实现，已用本地模拟接口验证请求格式，未用真实密钥实测。

## 一、怎么选（先看这张表）

| 资产类型 | 首选 | 理由 |
|---|---|---|
| 人物三视图（16:9 单图：左正背全身 + 模糊脸，右大头像） | **Image 2.5（sunburst）** | 能严格执行复杂版式、左右方位、模糊脸椭圆、计数；4K |
| 状态变体（湿透、脱雨衣） | **Banana 2 / Pro** 编辑 或 Image 2.5 带参考 | 以原三视图为底改状态，脸和版式最稳 |
| 强表情单图 | Image 2.5 | 需要按格排版 |
| 道具状态单图（多态并排、计数） | Image 2.5 | 计数与并排最准 |
| 场景主图（氛围、材质、光） | **Banana 2**（要更强照片感时 MJ 出氛围参考） | Banana 2 原生 5.5K、空间与夜景听话；MJ 质感最强但多米上只有 1456×816 |
| 场景 4/6 宫格多视角 | **Banana 2 / Pro** 编辑（以主图为参考） | 多参考一致性最好，同一地点换机位 |
| 首帧 / 关键帧（带人物） | Banana 2 / Pro（人物图 + 场景图多参考）或 Image 2.5 | 要锁脸锁空间 |

一句话：**版式与计数交给 Image 2.5，场景与一致性交给 Banana 2，国风与东方面孔可以试 Seedream，Midjourney 只做氛围参考。**

### 按手里有什么 API 来选

| 你接了 | 人物三视图 / 道具 | 场景 / 宫格 / 状态变体 / 首帧 | 说明 |
|---|---|---|---|
| 多米（一个密钥全有） | Image 2.5 sunburst | Banana 2 | 实测最完整的组合，**首选** |
| OpenAI + Google | GPT Image（官方最新图像模型） | Gemini 图像（Banana 2 / Pro） | 两家官方，稳定；OpenAI 官方尺寸上限较低（约 1536×1024） |
| 只有 Google | Banana Pro 出三视图（版式略弱，出图后重点查模糊脸和左右） | Banana 2 | 一个密钥能跑通全流程 |
| 只有火山方舟 | Seedream（版式与计数逊于 Image 2.5，出图后逐项核对） | Seedream | 国内直连、中文提示词；和 Seedance 同属字节系 |
| 只有 OpenAI 兼容中转 | 中转上的 GPT Image（`COMPAT_BASE_URL` + `COMPAT_API_KEY`） | 同左；中转若转发 Gemini 原生接口，把 `GEMINI_BASE_URL` 指向它 | 看中转支持哪些模型 |

脚本的顺延规则：推荐模型没有配好接口、或文档里没有它的代码块时，按 `config/image_providers.json` 的"按资产类型推荐"顺延到下一个模型。所以资产文档里**推荐模型给一个代码块，备选模型再给一个**，接口不全也能出完。

## 二、Image 2.5（gpt-image-2.5）

### 多米接口（实测）
- 提交：`POST https://duomiapi.com/v1/images/generations?async=true`，Header `Authorization: <key>`。
- 查询：`GET https://duomiapi.com/v1/tasks/{id}` → `data.images[0].url`。
- 字段：`model`、`prompt`、`size`（像素，如 `3840x2160`）、`n`、`image`（参考图，**只能是 URL 数组**，base64/data URI 返回 400）。
- 模型：`gpt-image-2.5-sunburst`（质量版，默认）｜`gpt-image-2.5-flare`（快速版，长边上限 2000，质感差，不用于交付）。
- sunburst 尺寸不稳定：同样请 3840x2160，人物图返回 3840x2160，场景图返回过 2000x1125。脚本应检查尺寸、不足则重出一次。
- 夜景暗部偶有方块压缩痕迹；屋檐"滴水"容易画成冰挂——写成"rainwater running off the eaves in thin continuous streams"并加"no ice"。

### 写法
1. **完整英文句子 + 中文锁定段**：先一句话说明图的用途和介质（"photographic character reference sheet… real person photographed in a studio"），再贴 `LOCKED … (verbatim)` 的中文描述锁。
2. **版式写成坐标**：LAYOUT 段逐块写"左半/右半、几个视图、等大、从头顶到靴底"。
3. **必须看得清的东西单列**（MUST BE READABLE），左右方位写成"her LEFT … appears on the RIGHT side of the image"。
4. **计数单列**（EXACT COUNTS）。
5. 最后一句写"画面里只包含……"，再列不要的东西（no text, labels, watermarks）。它对否定句的执行比 MJ 好，但仍以肯定描述为主。
6. 长度：2000–4000 字符都能执行；越长越要分段。

## 三、Midjourney

### 多米接口（实测）
- 提交：`POST https://duomiapi.com/api/midjourney/imagine/fast`，Header `Authorization: <key>`，Body `{"action":"generate","prompt":"…"}`。约 0.28 元/次。
- 查询：`GET https://duomiapi.com/api/midjourney/feed?task_id=…` → `state`（pending/running/succeeded/error）、`image_url`（四宫格总图）、`image_urls`（四张单图，外链 403，下载不了）。
- 当前是 **V7 行为**：总图 2912×1632（16:9），每格 1456×816。
- 取单图：`{"action":"upsample2","image_id":"<generate 的 task_id>"}` → 1456×816 单图（再计一次费）。
- 2 倍放大（Upscale Subtle/Creative）：`upscale_subtle`、`upsample_v7_2x_subtle` 都能提交，但都 `task timeout` 失败（已退费）——**多米上 MJ 放大不可用，单图上限 1456×816**。
- 平台会用 GPT 把中文翻译成英文；我们直接写英文，避免翻译走样。

### 写法（V7；V8.x 差异见下）
1. **结构**：`[参考图URL…] 主体与场景 → 构图/机位 → 光 → 介质/镜头 --参数`。图片 URL 必须放最前，参数放最后，参数后不再写字。
2. **长度**：正文约 50–150 词（≤1024 字符）。超过后效果递减；三视图那种 3000 字的说明书式提示词不适合 MJ。
3. **自然语言具体描述**：写看得见的东西（材质、颜色、光源位置），少写抽象形容词。"a single thin vertical line of warm amber lamplight in the door gap" 优于 "moody lighting"。
4. **否定只用 `--no`**：正文写 "no people" 反而可能画出人。`--no` 3–5 个具体词，如 `--no people, text, moon, snow`。
5. **写实参数**：`--style raw --s 0~100`（50 左右最稳），`--ar 16:9`；要更多变化加 `--c 10~30`。
6. **介质与镜头**：`documentary location photograph`、`35mm film photograph, fine grain`、`24mm wide`、`85mm portrait`；可用摄影师/导演名锚定风格，**不用演员名**。
7. **参考图**：
   - 图片提示：URL 放开头，`--iw 0~3`（默认 1）控制像不像。
   - 风格参考：`--sref <url> --sw 0~1000`，正文只写内容不写风格。
   - 人物/物体一致性（V7）：`--oref <url> --ow 0~1000`（默认 100；写实保脸 100–300），一次只能一张 oref，且费用翻倍。
8. **夜景**：MJ 会把夜提亮成蓝调黄昏。写 "deep night, black sky, almost no ambient light, the only light is …"，并 `--no dusk, twilight, blue hour`。
9. **不擅长**：多格精确版式、模糊脸椭圆、左右方位、精确计数、文字。这类资产不要交给它。

### V8.x 差异（平台若升级到 V8 时用）
- 原生 HD 2048px（`--hd` 或平台 quality 字段），无单独放大步骤。
- `--raw` 取代 `--style raw`；**不支持 `--oref`/`--cref`**（用编辑模型替代），`--q` 不可用；`--sref` 最多 20 张。
- 写实 `--s 50~150`。

## 四、Nano Banana 2 / Pro（Gemini 图像）

### 多米接口（实测）
- 文生图：`POST https://duomiapi.com/api/gemini/nano-banana`；编辑：`POST https://duomiapi.com/api/gemini/nano-banana-edit`。返回 `data.task_id`。
- 查询：与 Image 2.5 共用 `GET https://duomiapi.com/v1/tasks/{id}` → `data.images[0].url`（返回 JPEG）。约 40 秒出图。
- 实测 Banana 2 + `image_size: "4K"` + `aspect_ratio: "16:9"` 返回 **5504×3072**。
- **参考图单张不得超过 10MB**（报"图片大小超过 10MB"）；Image 2.5 的 4K PNG 常超限，所以依赖 Image 2.5 大图的改图任务要么改用 Image 2.5 出，要么先把参考图缩到 10MB 以内。超限有时只报"未知原因"。
- 改图任务也要传 `aspect_ratio`，不传会跑成 4:3（4800×3584）。
- 宫格多视角：漫水路这类开阔场景一致性好；石屋、石阶这类有左右结构的建筑，Banana 会把窗、台阶左右镜像，宫格改用 Image 2.5 出。
- 字段：`model`、`prompt`、`image_urls`（**仅 URL**，最多 10 张）、`aspect_ratio`（`16:9` 等；单张参考图时建议不填，让它跟随原图）、`image_size`（`1K`/`2K`/`4K`，大写 K；仅 Pro 和 2 支持）。
- 模型与价格：Banana 2 = `gemini-3.1-flash-image-preview`（0.1 元，1K/2K/4K）；Banana Pro = `gemini-3-pro-image-preview`（0.15 元，1K/2K/4K）；Banana 2.1 = `gemini-nano-banana-2.1`（0.08 元）。

### 写法
1. **像跟摄影师说话**：完整叙述句，说清"这是什么图、给谁用、画面里有什么、光怎么来"，不堆关键词。
2. **编辑任务写"保持 + 改变"**：先写保持不变的（"Keep the same woman, same face, same layout of the three views"），再写只改的（"make every garment soaking wet…"），最后写别动的（"do not change the background or the layout"）。
3. **多参考图逐张说明用途**："Image 1 is the character sheet — use her face and outfit. Image 2 is the location — use its walls, door and light."
4. **一致性强项**：同一人物换状态、同一场景换机位（宫格多视角）、把人物放进场景做首帧。
5. **4K**：`image_size: "4K"`；文字渲染与计数比 MJ 好，接近 Image 2.5。
6. **弱项**：照片质感不如 MJ；超长说明书式提示词会丢细节，控制在 300–1500 字符。

## 五、本片实测结论（《潮水来之前》）

| 模型 | 测试图 | 结果 |
|---|---|---|
| Image 2.5 flare | 15 张 | 版式对，质感塑料、长边 2000，不用 |
| Image 2.5 sunburst | 岚三视图 / 石屋门外 | 三视图 4K、皮肤毛孔真实、版式全对；场景只回 2000×1125，暗部有压缩块，屋檐画成冰挂 |
| Midjourney（V7） | 石屋门外 | 质感最好（照片级石墙、湿碎石、细水线）；夜被提亮成蓝调黄昏、多了草、窗板是关着的；单图 1456×816，放大两次都超时失败 |
| Banana 2 | 石屋门外 | 原生 5504×3072；夜色、雨向、墙在画右、开着的窗板、门缝唯一暖光都对；多画了一扇小窗，墙面有一点无来源的补光、纹理略锐 |

**本片结论**：人物三视图、表情、道具用 **Image 2.5 sunburst**（版式最准，4K）；场景主图、场景宫格、状态变体、首帧用 **Banana 2**（5.5K、指令和空间最听话、0.1 元）；Midjourney 在多米上只有 1456×816 且放大不可用，只作氛围/风格参考（`--sref` 或给 Banana 当风格图），不做交付资产。

## 六、Seedream（火山方舟 / 即梦图像）

### 接口（按官方文档实现，未实测）
- `POST https://ark.cn-beijing.volces.com/api/v3/images/generations`，Header `Authorization: Bearer <ARK_API_KEY>`。
- 字段：`model`（控制台开通的 Seedream 版本 id，设在 `ARK_IMAGE_MODEL`）、`prompt`、`size`（`2K`/`4K` 或像素）、`image`（参考图：URL 或 base64 data URI，单张写字符串、多张写数组）、`response_format: "url"`、`watermark: false`、`sequential_image_generation: "disabled"`（一次一张）。
- 返回 `data[0].url`。脚本把参考图压到长边 2048 的 JPEG 再内联。

### 写法
1. 中文自然语言即可，结构同 Banana：这是什么图、给谁用、画面里有什么、光从哪来。
2. 多参考图逐张说明用途（"图1是人物设定，只取脸和服装；图2是场景，只取墙、门和光"）。
3. 擅长东方面孔、国风服饰与建筑、水墨与工笔质感；版式、左右方位和计数不如 Image 2.5，三视图出完逐项查。
4. 文档里写 ```seedream 代码块；没写时脚本用 ```banana 代码块（写法相近）。

## 七、接口配置（用户只需填密钥）

1. 复制 `.env.example` 为 `.env`，填你有的那几家密钥（填一家就能跑）。
2. `python3 -I tools/image_gen.py --providers` 看哪些接口已经可用、每个模型会走哪家。
3. `python3 -I tools/image_gen.py 交付/01-资产提示词.md --out 交付/资产图 --dry-run` 看每张图走哪个模型、哪个接口、依赖哪张参考图——**不调用、不计费**。
4. 去掉 `--dry-run` 正式出图。已存在的图自动跳过；`--only 3,5 --force` 重出指定几张；`--engine banana` 强制全部用某个模型；`--provider google` 强制走某家接口。
5. 换模型版本不用改代码：在 `.env` 里设 `OPENAI_IMAGE_MODEL`、`GEMINI_IMAGE_MODEL`、`ARK_IMAGE_MODEL`、`DUOMI_MODEL`、`DUOMI_BANANA_MODEL`。

注意：
- 参考图依赖跨接口时，多米只认 URL：前一张图不是在多米出的，就让这一张也走同一家（`--provider`）。
- 出图是付费调用：助手不替用户出图，除非用户明确要求并确认花费。
