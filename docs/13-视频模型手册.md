# 13 · 视频模型手册：Seedance 2.5 / 可灵 4.0 / 海螺 03 / 万相 3.0

> 用途：一个故事做完镜头规格单（docs/14）之后，可以选任意一个模型出片。本手册写清每个模型的硬参数、模式、素材写法、提示词写法和已知故障，编译器（`tools/compile/`）按本手册把同一份规格单编成各家的投喂稿和 API 请求。
> 来源标注：【官方】= 厂商官方文档或用户指南（2026-11 核实）；【第三方】= 平台转述，未与官方核对；【实测】= 本工厂出片记录。参数以出片当天的界面为准，界面和文档不一致时听界面的。

## 二、选型：镜头类型 → 推荐模型

| 镜头 / 需求 | 首选 | 理由 | 备选 |
|---|---|---|---|
| 多人调度、过肩、纵深，要镜头路线精确 | Seedance 2.5 + 白模 | 白模当 @视频1，切点和走位跟得最准【实测】 | 可灵 4.0 + 白模 |
| 30 秒一条，中间有好几个必须定住的画面 | 可灵 4.0 关键帧 | 最多 10 个关键帧，可放在任意时间点【官方】 | Seedance 首尾帧 + 拆条 |
| 高速动作、追逐、多主体同时运动 | 可灵 4.0 | 官方定位就是快速运动和大运镜【官方】 | Seedance + 白模 |
| 短而精的表演和对白、要复刻音色 | 海螺 03 | 可以按参考音频复刻音色，2K 画质【官方】 | 可灵 4.0（方言、口型） |
| 大量试错、预演成片 | 万相 3.0 480P / Seedance 样片 | 最便宜【官方】 | 可灵 Flash |
| 镜头内要出现文字、字幕、标志 | 可灵 4.0 | 文字在运镜和转场中保持稳定【官方】 | — |
| 已有成片局部要改 | Seedance 2.5 编辑 / 可灵 4.0 编辑 | 只改指定部分，其余不动【官方】 | 万相 3.0 编辑 |

**混用原则**：一个故事可以按镜头选不同模型，但同一场戏内不换模型（质感和角色会跳）。换模型一律在硬切处换。

## 三、四家通用的写法（跨模型的工厂规则）

这些规则来自各家官方指南的共同部分，加上本工厂的事故复盘，对四个模型都适用。

1. **素材只管外观，提示词只管变化**：身份、服装、空间交给参考图；提示词写动作、镜头、时间和声音。四家官方都说"给每个素材写清职责"。不要在提示词里把人物从头到脚再描述一遍：海螺官方明确说这样做身份反而保不住；Seedance 官方建议中文 ≤ 500 字。
2. **每段一件事**：每个时间段只发生一个主要事件。Seedance 官方建议 15 秒 3–4 个节拍。
3. **画面里有谁**：每一镜开头写明画面里有谁。【实测：不写的话，模型会自己加人、加镜头】
4. **说话人可见**：每句台词放在说话人是主体的镜头里，或者放在说话人背对镜头的过肩镜头里；齐声安排在背对镜头的群像里。【实测：台词写在全景里，模型自己给说话人加了一个近景，把后面所有镜头往后推了 3.5 秒】
5. **界面时长 = 规格时长 = 白模时长**。【实测：差 5 秒，模型多出一个镜头】
6. **动作写物理**：方向、距离、速度、接触、结果；不写"跑向"这种开放动作。【官方 · Seedance】
7. **肯定写法**：约束写成"是什么"，不写"不要什么"。可灵官方说负面提示会增加出错；只有"无字幕""无背景音乐"这类声音和画面层面的开关可以写成否定句。
8. **形状说死**：容易被画走样的道具，每次出现都写同一个外形，比如"一根光滑的圆柱形银色金属针"。【实测：只写"塔"，被画成了铁架塔】
9. **轴线、过肩、遮挡、纵深**：见 `projects/最后一次采血/02-世界观与美术设定.md` 第六节，下一版写进 docs/02。
10. **改一处，只改一处**：翻车时只诊断一个故障、只改一句，不要整段重写。【官方 · Seedance】

## 四、Seedance 2.5

**模式**【官方】（三种互斥）：
- 文生视频；
- 首帧 / 首尾帧，ratio 必须是 adaptive；
- 全能参考，又分为参考、编辑、延长三种，用 `omni_reference_task_type` 指定，不确定时用 `auto`。

**API**【官方】：
- `POST https://ark.cn-beijing.volces.com/api/v3/contents/generations/tasks`；
- `content` 数组里放 `text`，以及 `image_url`、`video_url`、`audio_url`，用 `role` 标职责：`first_frame`、`last_frame`、`reference_image`、`reference_video`、`reference_audio`；
- 主要参数：`resolution`、`ratio`、`duration`（4–30 或 -1）、`generate_audio`、`return_last_frame`、`draft`、`output_format`、`callback_url`；
- 素材要用公网 URL、Base64 或 `asset://`。

**写法**：
- 素材职责句：每张参考图一句，说清"只取什么、不取什么"。白模视频要写明"只取镜头路线、切点、构图、走位"。
- 时间轴："0–4 秒｜镜头1 名字（同预演 0–4 秒）：画面里：……"。
- **字数**：官方建议中文 ≤ 500 字。本工厂的折中：
  - 核心提示词 ≤ 1200 字：职责句 + 时间轴 + 声音；
  - 外貌、空间这些长描述锁交给参考图；
  - 编译器默认出"精简版"，另附"完整版"作对照。
- 编辑提示词要包含"编辑视频 / 删除 / 替换"这类关键词；延长提示词要包含"续写 / 延长"。【官方】

**已知故障 → 修法**：
| 故障 | 修法 |
|---|---|
| 背景多出人物【官方】 | 写明"画面里有谁" |
| 运镜指令互相打架，被忽略【官方】 | 一镜只写一个主运镜 |
| 延长段接不上【官方】 | 开头先复述上一段最后的构图 |
| 模型自己加镜头【实测】 | 遵守通用第 4、5 条 |
| 道具变形【实测】 | 遵守通用第 8 条 |

## 五、可灵 4.0

**模式**【官方】（两个入口互斥）：
- **全能参考**（默认）：图 ≤ 10、视频 ≤ 5（共 30 秒）、主体 ≤ 7、音色 ≤ 3，合计 ≤ 15 个；
- **关键帧**：只收图片，最多 10 张，可以作首帧、首尾帧或中间帧；
- 编辑：最多 5 段，其中 1 段主视频；
- 延长：即将上线。

**写法**【官方】：
- 结构分四块：
  1. 素材职责：每个 @ 定义什么、保留什么；
  2. 总体设定：场景与质感、视觉风格、镜头调性；
  3. 事件顺序：按时间段写画面、动作、运镜和收尾镜头；
  4. 声音：对白、环境、音乐、音效。
- 硬切镜头清单写成 `SHOT 1 — 0.0–4.0s: ……`；关键帧写成 `0.0–2.1s | Keyframe 1 ……`。
- 对白放在引号里，用目标语言写；音色要描述年龄、音调、语速、情绪。
- 用具体描述（光、材质、构图），不用"高级感"这类抽象词。
- 风格是动画时要写明不要写实，例如"3D 动画质感，非真人实拍"。
- 编辑要写"Edit @Video1"，并加"其余保持不变"。写成"Reference @Video1"会被当成参考生成。

**本工厂的用法**：
- **有白模的条**：用全能参考，白模作 @Video1，只取运动和空间。
- **需要把画面钉死的条**：用关键帧模式。注意关键帧必须是成片画面，不能直接用灰色白模截图，否则会画成灰方块。做法是：
  1. 从白模按切点截出构图；
  2. 用出图模型按资产图重绘成首帧图；
  3. 再交给可灵。

  这一步要额外出图，费用先报给你。

## 六、海螺 03（MiniMax H3）

**模式**【官方】（互斥）：
- 文生视频：ratio 不能是 adaptive；
- 首尾帧：图片标 `first_frame` 和 `last_frame`；
- 参考生视频：参考图 ≤ 9、参考视频 ≤ 3、参考音频 ≤ 3。

**API**【官方】：
- `POST https://api.minimax.io/v2/video_generation`；
- 必填：`model`、`content`、`resolution`、`duration`；
- `content` 里 `text` 最多 7000 字；
- 素材可以用公网 URL、`mm_file://` 或 Base64，请求体 ≤ 64MB。

**写法**：
- 写成一份短的简报：主体、整条的动作、镜头、光、声音；
- 用"参考视频 1 的运镜""参考音频 1 的音色"这样的自然语言绑定素材；
- 不要在提示词里重复描述人物外貌；
- 同一个角色每次都用同一组参考：2–4 张图 + 1 段视频 + 1 段音频。

**本工厂的用法**：
- 单条最长 15 秒，**编译器按规格单的硬切点把一条拆成若干个 ≤ 15 秒的子条**。接缝都落在硬切上，不需要画面连续，只靠参考保证人物一致。
- 白模也按同样的切点截成子段，作"参考视频 1"。

## 七、万相 3.0

**模式**【官方】：
- 文生视频；
- 首帧 / 首尾帧（和参考、文件、链接互斥）；
- 参考生视频：图 ≤ 10、视频 ≤ 5、音频 ≤ 5；
- 视频编辑、视频延长；
- 文档 / 网页生视频。

**API**【官方】：
- `POST https://{WorkspaceId}.{region}.maas.aliyuncs.com/api/v1/services/aigc/video-generation/video-synthesis`，请求头必须带 `X-DashScope-Async: enable`；
- `input.prompt` ≤ 20000 字，`input.media` 用 `type` 标职责：`reference_image`、`reference_video`、`reference_audio`、`first_frame`、`last_frame`；
- `parameters`：`resolution`、`ratio`、`duration`、`audio`、`seed`、`prompt_extend`、`watermark`；
- 用 `GET /api/v1/tasks/{task_id}` 查询任务，结果链接 24 小时内有效。

**写法**：
- 素材叫"图1""视频1""音频1"，按同类型的顺序编号；
- 多镜头写"第1个镜头[0-4秒]：……"；
- **`prompt_extend` 关掉**：默认开着时模型会改写你的提示词，精确控制会丢。

**本工厂的用法**：
- 参考视频总长不超过 15 秒，而且输入加输出不超过 30 秒。所以带白模的条，**按硬切点拆成 ≤ 15 秒的子条**（同海螺）。
- 先出 480P 当便宜的预检，再出正式片。

## 八、按模型拆条

规格单里一条戏的时长 T，按模型处理：
- **Seedance、可灵**：T ≤ 30，一次出。
- **海螺、万相**：
  1. 从头往后累加镜头时长，超过 15 秒之前，在最近的硬切处断开；
  2. 白模同样截成子段；
  3. 每个子条单独编译，台词和声音只写子条里的部分；
  4. 剪辑时按切点顺序拼回来。
