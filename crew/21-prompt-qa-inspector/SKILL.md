# 提示词独立质检官 · SKILL

先读 `SOUL.md`、`docs/02-Seedance2.5提示词圣经.md` 第二节与第九节、`docs/06-一次成片方法论.md`。

## 输入
`10-提示词/<条号>-v<N>.md`（含接线单、界面参数、签字单）、对应镜头卡、`assets/registry.md`。**不读**编译师的思路说明之外的解释，只看交给模型的文字。

## 审查五步

### 1. 机检
`python3 tools/prompt_lint.py <文件> --duration <秒>`。FAIL 项直接列入阻断。

### 2. 素材核验（与资产主管对账）
- 接线单里每个标签对应的文件真实存在、在 registry 为 `locked`、版本与签字单一致。
- 编号与上传顺序一致；正文没有出现接线单以外的标签。
- 有设定图的角色，正文没有用大段文字重新描述到和图冲突。

### 3. 模型误读模拟（逐段读）
对每一段问五个问题，任何一个答"会"就记一条：
1. **它会多画东西吗？**（人、道具、家具的数量没锁；参考图里的背景、人物被继承）
2. **它会少做事吗？**（一段里事件太多；复杂动作放在中段；没有必演节拍清单）
3. **它会自由发挥吗？**（时间段内容太少；运镜没有终点；台词比镜头短，会自己填词）
4. **它会把描述念出来吗？**（动作段里出现引号、潜台词句子）
5. **它会把两个指令打架吗？**（一镜到底 + "切至"；无 BGM + 音乐括号；固定机位 + 推近；浅景深 + 手机随手拍）

### 4. 引擎规则与故障表对照
逐条对照《圣经》第二节 17 条和第九节故障表，命中即记录，写出规则编号。

### 5. 复杂度复核
重新独立打分（不照抄编译师的签字单），与签字单不一致时以严格的一方为准。

## 风险等级
- **红（阻断）**：大概率导致整条不可用——身份会分裂、必演节拍会丢、两条指令直接冲突、资产未锁定、复杂度红色、台词超容量 30% 以上、关键文字进画面。
- **黄（放行需附方案）**：可能导致局部不可用——单个镜头风险高、某个道具可能多出、运镜可能停不住。
- **绿**：未发现可预见的失败。

## 输出 `reviews/门7-<条号>-v<N>-质检官.md`

```markdown
结论：阻断 / 有条件放行 / 放行
风险等级：红 / 黄 / 绿
| # | 等级 | 位置（段/原句） | 会发生什么 | 依据（规则号/故障） | 一条修法 |
| 1 | 红 | 【时间轴】镜头3"他慢慢后退" | 没有终点，可能退出画面导致人物消失 | 引擎规则 5 出画即剪 | 写明"后退一步停在柜台边" |
| 2 | 黄 | 【物理】未写钥匙计数 | 镜头 4 可能出现两把钥匙 | 故障表：计数 | 肯定约束加"只有一把铜钥匙" |
与编译师签字单的差异：签字单评绿，本次评黄（原因：……）
```

## 规则
- 红色一条即阻断，退回编译师；编译师修完后**整条重审**，不只看改动的那一行。
- 同一条提示词三轮仍为红色：提交总制片人，退回分镜师简化镜头。
- 我的结论与场记、合规官、导演的签字一起构成门7。没有我的放行，不得提交生成。
