# 白模预演导演 · SKILL

> **模式说明**：默认模式下，本岗位是拆数据时过一遍的视角，落到哪些字段见 `docs/09` 第二节，检查由流水线的机检和目检完成（`docs/18`）。本文件里的审核、门禁、PASS/FAIL 报告段只在完整模式（`docs/01`）里作为独立环节执行。

先读 `SOUL.md`。方法参考用户提供的 tygg-ai-film-studio 预演工作流（圆柱球头代理、简化手部、圆滑镜头路线、静态确认后再做动画）。

## 输入
剧本与分条表（每条时长、镜头、调度）、场景空间地图、画幅。

## 流程（两个用户确认点，之后直接交付）

1. **连接**：`mcp__blender__get_addon_status` 与 `get_scene_info` 确认 Blender 实例可用；不可用时给用户安装步骤，不强行继续。
2. **静态场景（确认点 1）**：米制、Z 向上。按空间地图摆出地面、墙、门窗、家具锚点、道具占位、关键地标；人物用代理：
   - 圆柱 + 球头：成人总高 H 取角色设定（无则 1.70m 估计），头径 0.20H，体宽 0.24H，圆柱长 H−头径，球头与圆柱相切；
   - 四段骨骼弯曲（坐、蹲、倒、转身用）；每个角色一个纯色识别色，前向用一块深色区域标出；
   - 需要看清递接/持物的镜头才加简化手。
   渲染 2–3 张静态截图（`look`）给用户看空间是否对。
3. **动画与相机（确认点 2）**：每条生成一个 Blender 场景或时间段（帧率 24，时长与分条表一致）：
   - 根节点负责路线与朝向，路线用弧线；视线渐进；
   - 相机按分条表：机位、视场角（焦距换算）、主运镜起止、速度均匀或缓入缓出；切镜处用独立相机标记；
   - 事件先后（谁先到、东西何时从谁手里到谁手里）对齐台词时间；
   - 中性灰光、无材质、无文字；曲线、轴、相机锥不渲染。
   导出 720p mp4（每条一个文件，命名 `previs_<条号>.mp4`，存 `交付/预演/`），给用户看。
4. **交付**：流水线模式下编译器自动把白模接进投喂包作为 `@视频1`；手写模式下，在 `交付/02-Seedance提示词.md` 每条的上传清单加入 `@视频1 = previs_<条号>.mp4`，素材职责第一行写：

```
@视频1 只提供本条的镜头路线、构图、空间布局、人物整体位置与路线、事件先后和结果位置；不继承圆柱球体外形、识别色、灰色无材质画面、中性光和僵硬姿态；脸、服装、表演、手部抓握、光与质感按下文和人物/场景图。识别色对应：<颜色>=<角色名>。
```

## 什么时候必须做（不等用户提）
满足《提示词圣经》第 24 条任一项就做，不再只是"可选"：一镜到底里人物与镜头距离变化超过 3 倍；有高度差的爬升或下降；地标在机位身后、画面里只能看到它的光；机位要后拉或升高到明确的终幅大小。

## 每条都出预演（A 预演版要用）
默认模式下每条只交 A 白模预演版（`docs/09` 第三节），所以每条都要有白模；流水线 previs 阶段按规格单自动渲染。推荐做法：按 `tools/previs/README.md` 给每条写一份镜头规格 JSON（场景方块、人物路线、镜头与切点），用 `python3 tools/previs/render_previs.py <规格.json> --out 交付/预演/` 无界面渲染出 mp4 和关键帧拼图。复杂地形才用 Blender MCP 手工搭。

## Blender MCP 连不上时
直接无界面渲染，不必等插件：`<Blender> -b --factory-startup -P <脚本>.py -- <输出目录> [--stills]`（`<Blender>` 用环境变量 `BLENDER_BIN`，默认 macOS 为 `/Applications/Blender.app/Contents/MacOS/Blender`，Linux/Windows 为 PATH 里的 `blender`），先出静帧核对构图，再出全帧，用 ffmpeg 编成 24fps mp4。可复用的脚本见 `tools/previs/`（`common.py` 方块场景、圆柱球头人物、关键帧、Workbench 渲染；`examples/` 是《潮水来之前》第 2 条、第 6b 条的手写脚本）。

## 规则
- 视频参考单段 2–30 秒，与本条时长一致；合计不超过 30 秒（每条只上传本条预演）。
- 用户认可预演后不追加复核；只改提示词不重做预演，结构要变才回 Blender。
- 重操作串行，出错先 `get_scene_info` 查已完成部分。

## 顶级标准（docs/20）

本岗位的产出先过 `docs/20-顶级标准.md`：第一节（不做等救主式电子垃圾）、第四节（每条视听丰富度预算，含"张力：不要四平八稳"），再过下面这几条。交出去之前问自己一句：这一步做到顶级影视团队的水平了吗？没有就改，不等别人指出来。

- 白模只管结构：机位、走位、切点、节奏；先看节奏对不对，再看构图。
- 几何检查和拼图目检过了才交，WARN 也要处理。
